# Идеи для доработки

## Версия 1.0.1 (план)
- [x] Автоматическая синхронизация данных при входе/запуске, если синхронизации давно не было и виджеты находятся в одной локальной сети (сейчас только фоновая попытка ~раз в сутки) — реализовано на мобильном: при запуске `App.tsx` вызывает `performSync(false)`, тот же суточный троттлинг, что и у фоновой задачи, но без ожидания, пока ОС сама её запустит; десктоп синхронизацию не инициирует, только принимает входящие запросы через `LocalSyncServer` — проверено вживую: на десктопе была пустая база, на телефоне 6 растений; после запуска приложения на реальном телефоне (Wi-Fi, та же сеть, что и десктоп) данные автоматически подтянулись на десктоп без нажатия «Синхронизировать сейчас»
- [x] Временная синхронизация телефон↔десктоп по локальной сети (двустороннее слияние по `updatedAt`, тем­стоуны для удалений, IP десктопа вводится вручную в настройках телефона, фоновая попытка ~раз в сутки) — реализовано и проверено вживую на реальном телефоне и десктопе в одной Wi-Fi сети, включая удаление растения и повторную синхронизацию (не воскресает)
- [x] Поле «дней с последнего полива» при добавлении растения — иначе новое растение всегда считалось политым сегодня
- [x] Дата последнего полива в редактировании растения (сейчас поле «Дней с последнего полива» показывалось только при добавлении) — реализовано на десктопе (`AddPlantWindow` + `PlantItem.SetLastWatered`) и мобильном (`PlantFormModal` + `initialLastWatered`), проверено вживую на обеих платформах: изменение значения с 0 на 3 у «Ктенанты» (интервал 5 дн.) корректно пересчитало срок полива с «Через 5 дн.» на «Через 2 дн.»
- [x] Звук уведомления вкл/выкл — реализовано на десктопе (тумблер в `SettingsWindow`, `AppSettings.SoundEnabled`, `App.ShowNotification` проигрывает `SystemSounds.Asterisk` только если включено) и мобильном (`Switch` в `SettingsModal`, persist в `storage.ts`; на Android звук привязан к каналу уведомлений, поэтому завели второй, тихий канал `watering-silent` и переключаем канал в `rescheduleAll` по настройке), проверено вживую на обеих платформах
- [x] Фото цветка в карточке (иконка вместо/рядом с названием) — реализовано на десктопе (`PhotoStore`, `PhotoBrushConverter`, `AddPlantWindow`) и мобильном (`PhotoPicker`, `photos.ts`), фото device-local и не синхронизируется (см. пункт ниже), проверено вживую загрузкой фото
- [x] **Обязательно:** синхронизация фото между десктопом и телефоном (PW-002) — реализовано base64-передачей фото прямо в теле `/sync` (`PlantDto.Photo/PhotoExt/PhotoRemoved`, `mobile/src/sync.ts`), с гейтингом по `lastSyncAt` (`AppSettings.LastSyncAt` на десктопе, `SyncSettings.lastSyncAt` на телефоне), чтобы не пересылать неизменившиеся фото каждый раз; конфликт — тот же LWW по `updatedAt`, что и у остальных полей; очистка осиротевших файлов при замене/удалении фото (как через синк, так и при ручном редактировании) — проверено вживую в обе стороны (десктоп↔телефон), включая удаление фото и подчистку файла. **Важно (PW-003):** при первой реализации был баг — на самой первой синхронизации (`lastSyncAt == null`) отсутствие фото у растения на одной стороне ошибочно трактовалось как «фото удалено» и стирало реальные фото на другой стороне, из-за чего были безвозвратно потеряны фото у всех растений на телефоне; исправлено (сигнал `PhotoRemoved` теперь возможен только если `lastSyncAt` уже был установлен раньше)

Отмена/Полить» — реализовано на десктопе (`ConfirmWindow` с настраиваемым текстом кнопки) и мобильном (переиспользован `ConfirmModal` с `confirmLabel`), проверено вживую на обеих платформах, включая нажатие «Полить» и обновление статуса
- [x] Экспорт/импорт списка растений (включая фото) — на случай переустановки/сбоя, и как резервная копия перед рискованными изменениями (PW-005). Реализовано на общем wire-формате `PlantDto`/`PlantWireDto` (том же, что у `/sync`), поэтому бэкап с одной платформы теоретически читается и на другой: десктоп — `Settings → Резервная копия`, `SaveFileDialog`/`OpenFileDialog`, `MainWindow.ExportBackup/ImportBackup`; мобильное — `Settings → Резервная копия`, `expo-sharing` (шаринг файла для сохранения) / `expo-document-picker` (выбор файла), `src/backup.ts`; импорт всегда требует подтверждения, т.к. полностью заменяет текущий список. Проверено вживую: на десктопе — экспорт реальных данных и импорт того же файла обратно (round-trip, включая фото, без потерь); на мобильном — экспорт (файл с корректным именем ушёл в шаринг, статус «сохранена») и импорт до диалога подтверждения на тестовом файле (не подтверждался, чтобы не потерять оставшиеся реальные данные без возможности восстановить на телефоне)
